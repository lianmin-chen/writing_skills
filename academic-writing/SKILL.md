# Academic Writing

本 Skill 管理写作协作过程。用户当前的明确要求优先于本 Skill 的一般写作偏好；已确认的写作任务与内容方案约束后续写作，后来的用户要求可以调整它们。参考材料约束事实、术语和科学含义：可按已确认的任务和内容方案取舍内容，不得曲解保留的内容或虚构依据。若要求、材料或已确认方案存在影响核心内容的实质冲突，说明问题及方案影响，由用户决定；已确认且未改变的事项不重复询问。

## 协作流程

### 1. 明确本次写作任务

识别**这次要做什么、最终交付什么文稿**：新建、整理或修改什么，文稿用于何处、面向谁、以什么材料为依据，以及已知的重要约束。对会改变交付物的歧义主动提出具体建议；参考常见文稿类型，但不要求用户选类别。开始时阅读[写作任务工作单元](workflows/01-writing-goals.md)。

- **输出**：必要时用简短自然语言提出可修改的任务定义；已明确的事项不重复汇报或确认。
- **完成条件**：本次任务和交付物已由用户说明或确认，且无影响后续规划的关键歧义，即可进入步骤 2；用户明确要求只讨论任务时停在本步。
- **边界**：不列完整知识目录，不逐项制定掌握层级，不安排内容顺序或写正文。

### 2. 构建写作大纲与脉络并确认

根据目标文稿和材料，确定**写哪些主要内容、各部分承担什么作用、如何组织与联系**；修改已有文稿时先审阅现稿及保留边界。阅读[大纲与脉络工作单元](workflows/02-content-plan.md)。

- **输出**：可供用户审阅和修改的写作大纲与论述脉络，说明主要内容、逻辑关系和必要的写作侧重；暂不写正文。
- **规范**：不以标题目录代替内容关系，也不强行将并列内容编成单一主线；不同文稿按各自任务组织，不套用知识讲解类示例。
- **完成条件**：用户确认内容安排与脉络后进入步骤 3；若方案实质改变已确认的文稿定位，先同步更新任务约定。

### 3. 正文写作

- **输入**：已明确的写作任务、已确认的内容方案与脉络、参考材料。
- **模型工作**：按各部分的目的安排详略，写出必要的定义、依据、条件和推理，选择合适的表达形式。
- **输出**：指定范围的正文草稿。
- **规范**：遵守下方按需读取的写作规范，忠实于材料；若必须改变核心含义或既定方案，先交由用户判断。
- **参考格式**：正文没有通用模板；段落、列表、公式等由内容和用户要求决定。
- **完成条件**：草稿覆盖已确认范围，进入质量自检。

### 4. 质量自检

- **输入**：正文草稿、写作任务、已确认的内容方案与脉络、参考材料。
- **模型工作**：对照任务与内容方案核查重点与取舍、逻辑与必要条件、事实与依据、表达质量及要求落实情况，修正可自行处理的问题。
- **输出**：修订后的正文；如有涉及用户关键决策的问题，明确说明。
- **规范**：不以字数减少或形式整齐代替质量判断，不把未解决的问题声称为已通过检查。
- **参考格式**：通常直接交付修订结果；仅在存在实质待决问题时说明问题及其影响。
- **完成条件**：可自行处理的问题均已修正，待决问题已如实反馈。

**第一步明确任务、第二步确认大纲与脉络；确认已在用户要求中体现时不再制造额外轮次。** “参考格式”仅提供可选的呈现方式，不是每次回复必须填写的模板。通用写作规范由下方参考文件承载。

## 按需读取

- 写正文或实质改写前，阅读[通用写作规范](references/writing-guidelines.md)；仅讨论目标或脉络时，按需要读取相关部分。
- 数学讲义、复习材料或类似教学任务，阅读[数学写作要求](references/math-writing.md)。
- 设计知识讲解类的完整脉络或需校准内容关系时，按需阅读[写作案例与对照](references/writing-examples.md)；仅该类已有用户认可的完整范例，不跨类型套用。
- 修改或回测本 Skill 时，使用[回测案例](tests/cases.md)；测试记录不作为普通写作任务的指令。
