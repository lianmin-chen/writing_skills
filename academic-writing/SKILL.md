# Academic Writing

先明确本次要完成的写作操作及目标文稿，再根据其用途选择、组织必要内容，完成准确、清晰、自然的写作。

## 执行边界

用户当前明确要求优先于 Skill 的默认偏好。已确认的任务、内容方案和必写内容约束后续工作；用户可以调整它们。忠实于材料的事实、术语、科学含义及证据，不虚构依据，不擅自扩大范围或改变核心结论。遇到实质冲突，说明影响，由用户决定。材料不可访问时如实说明。

## 按阶段加载与执行

**先判断当前处于哪个阶段，只读取该阶段工作单元及其指定的适用参考文件。** 每完成一阶段，依据其完成条件和用户授权决定是否进入下一阶段，再加载下一阶段指令。不提前加载后续阶段的执行规范和范例；各阶段的产物尺度由本阶段决定。已读取的共用规范可以沿用，无需重复读取。

| 阶段 | 执行指令 | 本阶段产出与移交条件 |
| --- | --- | --- |
| 1. 明确写作任务 | [写作任务](workflows/01-writing-goals.md) | 确定本次操作、目标文稿及关键限制；任务已明确或获确认后进入 2 |
| 2. 构建内容方案与脉络 | [写作规划](workflows/02-content-plan.md) | 充分分析材料、组织内容、建立论述脉络；方案获确认后按用户要求进入 3 |
| 3. 正文写作 | [正文写作](workflows/03-drafting.md) | 根据已确认方案写出指定范围的正文草稿；进入 4 |
| 4. 质量自检 | [质量自检](workflows/04-quality-check.md) | 修正实际问题并直接交付成稿；实质待决问题如实反馈 |

用户只要求某阶段时停在该阶段。任务或方案已由用户明确说明或确认时，直接沿用，不重复确认。正常执行不额外报告流程状态或展示未要求的中间分析。

**直接修改现稿：**任务和边界明确时，按修改对象进入相应阶段：修改任务定义用步骤 1，修改内容框架或脉络用步骤 2，修改正文用步骤 3，专项审查用步骤 4。只执行用户要求的工作及必要的自检，不重启全部流程；涉及已确认的核心目标、结论或范围的实质改变时，先由用户决定。

修改或回测本 Skill 时才读取 [回测案例](tests/cases.md)；普通写作任务不加载测试和设计记录。
