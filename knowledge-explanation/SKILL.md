# Knowledge Explanation

## 任务

结合知识对象的类型与用户实际的疑问，确定本次需要讲清的认识，以准确、清晰、自然的专业语言帮助用户理解知识。

## 确定讲解任务

识别用户所问的知识对象、具体疑问和已有知识基础。不同对象具有不同的认识重点：

| 知识对象 | 可能需要讲解的内容 |
| --- | --- |
| 概念 | 刻画什么对象或特征、为何引入、如何定义、实际含义 |
| 性质与结论 | 说明什么关系、成立条件、为什么成立、意义 |
| 方法与算法 | 解决什么问题、基本思想、关键操作、为什么有效、如何使用 |
| 理论与模型 | 研究什么问题、基本假设、核心思想、如何描述或解释研究对象 |
| 公式 | 描述什么关系、各项含义、成立条件、如何得到和使用 |

结合用户实际的疑问，从上述认识维度选择本次的讲解重点。例如，询问 Gram–Schmidt 正交化为何不改变张成空间，重点是解释新旧向量组的线性组合关系，而不是介绍完整算法。对于概念辨析，围绕造成混淆的实际区别和联系展开。对象类型可以重叠，不将认识维度作为固定栏目。

## 专业讲解

参考 [讲解范例](references/examples.md)，根据具体问题选择解释角度、必要知识和论述顺序。

- 以任务目的决定核心认识，以核心认识决定内容取舍，以必要性决定解释深度。
- 按照读者建立认识的顺序展开（Logical Flow），从已有知识引入新认识（Old-to-New）。直接讲清必要的中间关系，不用连接词或抽象概括代替具体解释。解释方法的基本思想或原理时，若涉及新的构造、辅助对象或关键操作，先明确需要解决的问题，再利用具体的条件或已有关系说明为何引入它，而不只在引入之后验证其性质和作用。
- 段落围绕明确的论述任务，给出必要的定义、事实、原理或推理，并说明由此得到的结论及其意义（Topic–Evidence–Link）。这些是写作方法，不是固定句式。
- 使用规范、准确、自然的专业语言，标题优先采用常用专业名称。直接表达对象及其关系，不为追求生动而使用含糊的比喻、口号或堆叠问句。根据理解需要使用公式、推导、例子、对比、图示或有科学依据的直观解释；明确成立条件、符号和对象，不把直观说明当作严格证明。

## 交付与完善

直接回答实际疑问，不罗列整个知识体系，不额外交付分析、脉络或审阅报告。必要时简明补充前置知识；根据用户要求调整解释深度。完成后通读并修正事实、推理、论述跳跃及不恰当表达。忠实于指定材料及事实依据，材料不足或存在实质歧义时如实说明，必要时澄清。以用户指定格式为准；Obsidian 笔记使用 Markdown，行内数学用 `$...$`，独立公式用 `$$...$$`。
