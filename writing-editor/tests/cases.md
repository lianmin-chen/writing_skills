# Writing Editor — 开发测试

用于开发评价，不作为运行时规范。不追求固定改写或审查条数。

- **专业表达：** “一个向量由基向量怎样表示，决定了它的像由这些基向量的像怎样表示。线性性使基成为认识整个变换的入口。” 要求审查并润色。应明确两个数学依据及结论，而不是只换同义词。
- **逻辑缺口：** 已介绍 SVD 的两侧选基思想，下一段直接陈述 $A^HA$ 的 Hermite 半正定性。要求审查基本原理是否清楚。应发现构造缘由缺失，并依据像向量的内积建立联系，不展开无关应用。
- **证据边界：** 同一测试集的误差为 A=0.18、B=0.22，无重复实验。“A 显著优于 B，说明泛化能力更强。” 要求审查并改写。应限制主张于当前观测，不补造证据。
- **保留恰当表达：** “由于任意向量都可以表示为基向量的线性组合，而线性变换保持这种组合关系，因此只要知道一组基向量的像，就能够确定整个变换。” 要求检查是否需要修改。应认可已恰当的论述，不为了修改而修改。
- **范围与交付：** 仅润色一段时不重写全文；只审查时不默认交付整篇修订稿；发现核心观点需要改变时说明并保留用户决策权。
- **迁移：** 后续使用真实的用户原创非数学文稿，观察能否发现具体问题并实施有效编辑，避免只验证已收录的范例。

评价依据是诊断是否有原文证据、修改是否真正解决问题、是否保留恰当内容及科学含义。参考原稿、用户反馈与实际修订差异。回归例已进入参考资源，不用于证明独立迁移能力。
