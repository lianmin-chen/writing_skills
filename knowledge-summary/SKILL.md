# Knowledge Summary

## 任务

以整体知识脉络为基础，围绕各个研究对象及其核心问题，系统地组织和表达理解与运用知识所必需的内容，形成能够独立阅读、理解和复习的专业知识文稿。

核心思想：以认识的需要决定内容的组织，而不是先罗列知识点，再寻找它们之间的关系。

## 工作方式

1. **理解知识与建立整体脉络。** 充分理解材料，识别核心研究对象及主要研究内容。对于整章、多主题或关系复杂的任务，先参考 [宏观脉络范例](references/macro-examples.md)，在内部形成一份简明、清晰的脉络稿，讲清各部分的研究动机、主要内容及作用，再以此确定正文的主题层次和论述顺序。已有用户确认的脉络直接沿用；范围较小、脉络明确时直接写作。无需额外交付脉络稿或要求确认。
2. **明确各主题的核心问题。** 围绕研究对象理解为什么研究、是什么、基本思想是什么、如何实现或使用、具有哪些性质及成立条件等，确定真正需要回答的问题。根据知识本身确定问题及顺序，不将这些视角设为固定栏目。
3. **组织必要的知识内容。** 围绕具体问题引入相关概念、原理、性质、结论、公式及方法。例如，为求解特征值而引入特征多项式，为判断相似对角化的可行性而引入代数重数与几何重数。
4. **撰写知识总结。** 写作前阅读 [专业写作指导](references/writing-guidelines.md)、[完整知识总结范例](references/vector-space.md) 和 [局部问题导向范例](references/diagonalization.md)。以已建立的脉络为基础展开正文，保留恰当的论述和层次。按照 Logical Flow、Old-to-New、Topic–Evidence–Link 的思想组织标题、段落和句子，充分讲清核心思想及必要知识，适当补充有依据的直观理解。这些是写作方法，不是固定模板。

## 交付尺度

默认提供可独立使用的知识总结，而非脉络稿、知识点清单或详细教材。整体范围的文稿通常先概述整体认识，再按主题展开正文，最后按需综合重要认识与知识联系；总结应提炼认识而非机械重复。局部写作沿用已有语境。保留必要的定义、条件、重要结论和可实际运用的方法；证明、推导、例子与计算过程按其对理解和运用的作用决定深度。不为精简省略关键依据，也不为完整而面面俱到。

标题准确概括各部分的实际内容，层次体现知识的从属与并列关系。根据内容选用段落、列表和公式；数学表达通常用行内公式，较长推导及需要独立突出的关系用行间公式。以用户指定格式为准；Obsidian 笔记使用 Markdown，行内数学用 `$...$`，独立公式用 `$$...$$`。

## 审阅与完善

参考专业写作指导及优秀范例，从专业教师和读者的角度整体审阅初稿：正文是否延续了原有脉络，标题层次是否合理且与正文相符，核心问题、思想与必要知识是否讲清，段落和句子的承接是否自然且有实质内容，知识是否准确、完整且详略得当。直接修正问题，保留已经恰当的内容与表达，仅交付完善后的文稿。

以用户明确的目的、范围、已有认识及材料为准；忠实于事实、科学依据和术语，不虚构结论或擅自扩充范围。关键材料缺失或存在实质歧义时如实说明，必要时澄清。
